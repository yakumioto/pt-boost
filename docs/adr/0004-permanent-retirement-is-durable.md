# 永久淘汰名单是持久状态，热种池仍从 torrentfs-go 恢复

生产环境发现冷种已删除但仍满足搜索人数条件，导致同轮或后续扫描重新添加；用户明确要求永久禁止复活，而不是有限冷却。为使此约束跨重启成立，pt-boost 持久化 torrentfs id 及已知站点 id 的永久淘汰名单，同时保存尚未完成的删除意图；热种池成员、上传采样仍不持久化。这修订了原先“pt-boost 无本地持久化”的假设，但不改变 torrentfs-go 负责解析 infoHash 的边界。

名单按站点名称与分类隔离，原子替换并同步落盘后才提交删除，异步操作成功才确认出池；失败/超时或进程中断后在启动及扫描时继续清理，不依赖搜索命中新候选。别名仅在真正添加后用 torrentfs-go 返回的 id 判定，若命中永久淘汰且本次新建则删除并持久排队；原本由别的片库管理的任务不删除、不认领。

数据目录必须可写且持久（Docker 命名卷），没有自动过期或解禁；数据卷丢失、修改站点名称或分类会丢失或切换名单，需要运维保留和备份。相比纯内存冷却，接受这份本地状态与备份成本，以换取真正的跨进程永久禁入。已有池成员不会因新增的 `seeders < 50` 候选过滤规则被立即批量清空，仍遵循冷种淘汰策略。
